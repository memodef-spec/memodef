memodef.org

The open standard for memo-message definitions.

memodef defines a portable, machine-readable format for memos that flow between positions in an organization — handoffs, replies, broadcasts, and announcements, delivered as .openthing files inside the recipient's working repository. Memos are files, not protocol messages: content is sovereign, transport is swappable, and the simplicity of the substrate is the moat.

POP-like by design

The simplest viable substrate that supports the use case, not the most feature-rich. POP beat IMAP, X.400, and JMAP for the median user because the floor was low enough for everyone. Worse-is-better.

Files, not protocols

Memos are catdef .openthing documents committed to the recipient's working repo as receipt-of-record. Notification (the path of the new memo) is a separate, swappable transport — file-watchers, channels, RSS, or a human steward.

Composes with roledef + orgdef

A memo's from and to are position ids declared in an orgdef artifact, which references roledef for what each role IS. memodef is the communication layer of the OAGP family.

Forward-compatible

v0.2 added body_ref for sibling .body.md long-form content; v0.1 memos remain conformant. Future enrichment temptations route to optional fields, the x.<domain>.<identifier> extension namespace, or get skipped. The spec stays small.

File Format

A memodef:Memo is a catdef .openthing document with these top-level fields:

{
  "catdef": "1.4",
  "memodef": "0.2.0",
  "type": "memodef:Memo",
  "from":    "<sender-position-id>",
  "to":      "<receiver-position-id>",
  "subject": "<short subject line>",
  "sent":    "2026-05-07T14:00:00Z",
  "body":    "<markdown content>",
  "in_reply_to":     "<optional>",
  "action_required": false,
  "thread_id":       "<optional>",
  "body_ref":        "<optional sibling .body.md filename>"
}

OAGP Family

memodef is part of the Open Agentic Governance Pattern family of open standards:

catdef roledef orgdef memodef
